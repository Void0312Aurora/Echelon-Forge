## Purpose

按依赖顺序完善 EW，并拆分为可审阅的 PR Stack。

## Current State

诱饵与基础干扰机制已在主分支；RF/ESM、发射预算、时序、编队角色和规范动作准入已通过本地验收。PR #103-#109 的常规检查通过，均待审阅；#104 的 CUDA 配置任务尚未闭合。E4-B 为 #108，E5 为 #109。E6 的两个命名终局代理场景已完成固定种子与重放验证。

## Scope

范围包括 ESM、干扰效果与资源、时序、协同、动作准入和命名终局场景。
具体装备的 RF 校准、发射机库、旁瓣与虚假航迹需要独立的来源和验收。

## Phase Plan

E1 RF/ESM → E2 干扰与资源 → E3 时序 → E4-A 共享命令投递 → E4-B 编队角色 → E5 动作准入 → E6 终局验收。E4-A 仅提供传输能力，不代表 Air EW 编队接入完成。

## Task Clusters

每簇一次实现与最多两次证据驱动的修复。扩大范围时单独登记后续簇。

## Outputs And Evidence

E1 分成数据契约与运行时观测两个 PR。接收功率使用自由空间参考；置信度表示
所需独立扫描的完成比例；相邻有效观测的间隔超过记忆时限后重新计数，
它不表示滑动窗口计数或探测概率。旧内容和默认观测键保持兼容。

E2 的完整 Jammer/雷达 RF 契约才允许按频段重叠干扰；旧式配置保留现有带宽代理。
发射 EIRP 仍只用于发射观测，干扰 burn-through 使用独立的 `power_watts` 标定。
可选预算必须同时配置突发上限与冷却时间；缺省仍为无限时长。DRFM 的正负偏移
仅改写同一目标的报告距离，不生成独立虚假航迹。

E4-B 通过显式的 `ew_formation_commanders` 启用同队、分世界的角色命令。只有当前
可用指挥成员可以发出有期限的 `emission_hold` 或 `self_protect` 授权；后者允许
成员自己的策略发射请求通过，不自动产生请求。到期、通信不可用或指挥切换会
撤销授权；恢复通信后需要新命令，旧指挥代次和较早命令不能重新覆盖角色。
过滤只覆盖 jammer 的动作索引 14-15，战斗前缀及本机 chaff/flare 保持独立。

E5 将 14 维 `air_ew_hybrid_v1` 与 16 维 `air_ew_hybrid_v2` 追加到规范动作列表。
配置/CLI、单机与协同训练工厂、原生资源与发射状态、可选 EW 状态和标准 PPO
更新通过聚焦验收；原有五项顺序及动作前缀保持稳定。v3 配置被拒绝，专用的
12 维 `hybrid_action_spec` 仍拒绝 EW 空间，没有扩展其混合分布语义。
配置/准入/EW 投影/bootstrap 选择通过 61 项测试和 2 项子测试；这不代表训练质量。

E6 的[冻结验收记录](artifacts/ew_named_terminal_acceptance_20261007.json)来自干净提交
`ef1073886b5e73749cc7b05aca782d3be1777edb`，附有场景、实际原生模块与重放轨迹哈希。
单机与 2v2 在种子 `20260516`、`20261007` 下均以 `combat_win` 终止，早于 600 步预算。
各受控成员都有原生武器发射、告警/请求对应、chaff/flare 库存下降和 jammer 发射读数，
同种子重放一致。验收器与现有演示通过 34 项测试；损坏/失败/超时/缺失证据和重放漂移
均被拒绝。这些负例验证验收器，不代表全部仿真失败/超时动力学已验证。

库存消耗从首次请求前一帧算至终局前一帧；终局步自动 reset，未将下一局库存计入。
两个场景的目标仍为通用 Aircraft 工程代理；库存减少与发射状态没有测量寻的器诱骗、
雷达压制或 EW 对获胜的因果贡献。E6 本地结论仅覆盖此命名工程门槛，Air/EW 可玩性
标签不提升。逐场景结果及剩余责任见[任务簇记录](ew_completion_task_clusters_20261006.md#e6-scoped-acceptance-receipt)。

## Acceptance Gate

以最后一次编译的代码执行负面用例、状态往返、EW 回归及 Python 内容/投影验证；
创建 PR 不等于通过审阅，E1 不等于取得可玩性验收。E3 将 `ew_state_history` 限定在显式启用 EW 状态且历史长度大于 1 的环境，并用有效帧遮罩排除 reset 补零；该遮罩只标记观测帧是否存在，不代表发射机存在、ESM 置信度或 RF 检测有效。默认观测布局不变。

## Residuals And Next Steps

确定性丢包/重放、TTL 到期边界、节点失效取消、Joint 慢决策周期过滤、原生
CommandLink 回归及任务边界检查。E4-A 的结果不包含 Air 编队角色；角色路由、
指挥丢失/重分配和成员/资源隔离由 E4-B 的验收提供。外部/支援干扰机组合尚未实现；
当前频段、burn-through 和平台效果仍是工程代理，
没有校准 J/S，也不生成虚假航迹生命周期。#104 CUDA 检查在工具链配置阶段超时，
尚未得到源码编译结论。E3 本地的 PPO、确定性重放、checkpoint 往返及旧版非 EW 时序策略严格加载/前向等值检查已通过；
没有声称训练效果提升，远端 CI 与审阅仍待完成。当前导弹雷达分类仍是粗粒度发射机代理。

撤销与重分配、世界/成员/资源隔离、同种子重放和默认路径兼容。较广的协同回归
另有三项旧测试失败，已在原始 E4-A 环境代码 `f931d84c1` 上复现：Python 侧开火
授权修改、旧告警步号、空目标的 `int(None)`。它们尚未闭合，不能宣称完整协同
测试通过。原生 DataLink/CommandLink 状态自动映射和隐藏真值中的飞机损失推断
不属于本轮角色授权范围。E5 与 E6 的上述本地门槛通过；真实平台 EW 终局效果、
支援干扰、独立虚假航迹和可玩性验收仍需后续工作，责任归属详见任务簇。
