# 梯度真实性原则

Language:
- English canonical: `foundation/gradient_realism_principles.md`
- Chinese companion: [gradient_realism_principles.zh.md](gradient_realism_principles.zh.md)

状态：`2026-05-24`，多域真实性门控的基础层权威规则。

本文档定义项目在场景复杂度提升时如何处理领域真实性。它属于标准树的
foundation 层，因为该规则同时适用于 air、naval、ground、joint command、
sensor、weapon 以及未来领域。

核心规则是：

> 一个场景只能声明其所需领域机制已经实现、进入维护中的 runtime contract、
> 并有证据覆盖的最高真实性等级。

这避免把只适合简单巡航的模型，因为场景里加入了武器、对手或更多实体，就描述成可信交战模型。

## 目的

梯度真实性用于保持三件事一致：

- 场景复杂度
- 已实现的领域机制
- 文档、训练配置、评估报告和任务计划中的真实性声明

随着场景加入更多战术要求，最低真实性门槛也必须上升。只要求飞机巡航的场景，可以接受比
高攻角机动、传感器不确定性、武器投放和 ROE 约束都出现的空战场景更窄的飞行模型。

## 真实性不是单一开关

项目不使用一个简单的“真实 / 不真实”标签。真实性必须限定到当前场景实际训练或评估的层级。

示例：

- 航路跟随场景只要 route guidance、风场处理、速度/高度稳定性以及 reward/termination
  合理，就可以成立。
- 着陆场景必须额外具备 runway、approach、gear、flare、touchdown 等行为，才适合声明为着陆工作所需的真实性。
- 交战场景必须额外具备 sensor、track、weapon、ROE、damage/effects 与高机动飞行动力学，
  才能作为可信战斗训练场景。

通过较低门槛，永远不代表较高门槛也已经通过。

## 简化但可信的建模规则

项目默认目标不是研究级、工程级或全物理精确求解。对于大多数 runtime、场景和 RL
训练任务，更合适的目标是：

> 在可实现、可维护、可验证的前提下，构造尽可能真实的简化模型。

这里的“简化”是相对研究级或工程级模型而言，而不是相对游戏化或玩具化抽象而言。换言之，
项目不要求在默认情况下实现难以获得数据支撑、实现复杂度极高的全细节模型，但也不能因为追求
可训练性，就把已经声称具有战术真实性的域问题退化成只剩功能链路的开关拼接。

一个可接受的简化模型，至少应保留以下内容：

- 因果结构：关键状态、动作和事件之间的作用关系不能被抹平。
- 相对排序：更优 / 更差、更强 / 更弱、更近 / 更远的后果方向应基本符合现实战术常识。
- 后果链条：任务真正依赖的观测变化、约束、风险、窗口、损伤、失效或授权逻辑应在 runtime
  中留下可见后果。
- 可验证边界：模型声明的精度层级必须与当前可获得的数据、测试证据和实现能力相匹配。

一个不可接受的“伪高保真”模型通常具有以下特征：

- 数值看起来更细，但缺乏数据来源或合理校核，只是伪精度。
- 参数很多，但关键因果方向错误，导致策略学到的不是现实战术，而是实现伪影。
- 局部细节堆得很高，但任务真正依赖的后果链没有闭合。

因此，本项目追求的不是“默认做到工程级最细”，也不是“为了方便训练而默认做成游戏规则”，
而是位于两者之间、能够支撑战术推理与 RL 学习的可信简化模型。

该规则是跨域通用规则，不只适用于杀伤模型，也适用于飞行动力学、传感器、武器制导、电子战、
地海空平台行为、指挥链、后勤约束以及未来新增域。

## 梯度等级

以下标签是项目共享语汇。它们不是完整物理需求清单，而是最低声明边界。

| 等级 | 场景能力 | 最低真实性门槛 |
| --- | --- | --- |
| `G0` | 静态 setup / 实体存在 | 单位生成时具有一致的身份、阵营、位置和基础状态。 |
| `G1` | 稳定运动 / 巡航 | 运动学、速度/高度/航向响应、有限状态安全与基础能量行为足以支撑航路或巡航任务。 |
| `G2` | 航路、天气和编队任务 | 导航、风、航路几何、role/slot 可见性与多智能体间距语义在任务观测边界可见。 |
| `G3` | 起飞、着陆、回收、station 或地形约束执行 | 定义任务的领域专用 surface 或地形约束已经表示出来，并能一致地影响终止/奖励。 |
| `G4` | 传感器接触、汇报和共享态势 | 相关任务不再依赖隐藏真值；contact、track、classification、reporting 与 data sharing 具备显式可见性和质量语义。 |
| `G5` | 武器释放、ROE 和最小交战生命周期 | 武器授权、目标分配、发射约束、弹药/冷却、制导/效果事件和交战终止由维护中的合同表示。 |
| `G6` | 可信对抗空战或争夺性多域行为 | 高机动平台行为、传感器/航迹不确定性、武器包线、毁伤/效果、指挥授权与 reward/termination shaping 足够强，使策略成功不被非战术伪影主导。 |
| `G7` | 高级争夺真实性 | 电子战、欺骗、中继/时延约束、授权转移、多平台协同与领域专用对抗措施足以支撑场景声明。 |

各领域可以在这些标签下添加子门槛，但不应在局部重新定义这些标签。

## 声明规则

1. 场景真实性声明必须标出它实际满足的最高门槛。
2. 训练或评估结果不得暗示高于场景、runtime 与证据支持的门槛。
3. 功能接线进入 runtime 不足以提升门槛。该功能还必须在维护路径中影响 observation、
   reward、termination、diagnostics 或可追踪的 runtime product。
4. compatibility 或 diagnostics-only 路径不能建立维护中的真实性，除非该门槛明确允许。
5. 低门槛回归会阻断所有依赖它的更高真实性声明。

## 回归规则

当基础设施工作改变 runtime ownership、facade path、batch path、observation provenance、
action injection 或 compatibility gate 时，必须按当前活跃场景的最高门槛重新检查真实性。

如果这类工作之后出现新的失败模式，应在隔离前记录为可能的真实性回归。即使功能场景仍然能跑，也适用。

例如，若 `1v1` 空战场景仍能启动、探测目标并发射武器，但 episode 被深失速终止主导，
则该场景只是功能链路仍接通；在恢复飞行稳定性门槛前，不得声明为可信空战真实性。

## 跨域规则

多域场景受限于对任务有实质影响的最弱领域门槛。

示例：

- 海军防空场景即使舰艇运动可信，但目标分类泄露真值，也不能声明为可信 sensor/engagement 场景。
- 地面支援场景即使 tasking 合理，但没有 terrain-masked sensing，也不能声明为争夺性地面侦察真实性。
- 空战场景即使有武器发射和毁伤事件，但高攻角行为不稳定，也应停留在可信战斗真实性以下。

## 证据预期

每个门槛应有与风险匹配的证据：

- `G0-G2`：聚焦 runtime 测试、shape/roundtrip 测试与有限状态 smoke。
- `G3-G4`：场景专用 termination/reward 检查、观测可见性检查，以及任务关键量的 diagnostics。
- `G5-G6`：交战生命周期测试、authority/ROE 检查、flight/sensor/weapon 真实性守门，以及短 policy 或 scripted rollout diagnostics。
- `G7`：带可追踪 jamming、deception、relay、authority-transfer 或 coordination 证据的显式争夺行为测试。

证据只需要覆盖场景声明，不需要提前实现无关的高保真行为。

## 文档规则

任务文档和 README 应区分：

- 功能进度：场景路径能运行，或功能已经接线
- 真实性门槛：当前支持的最高梯度等级
- 阻断性真实性回归：会阻止更高声明的低门槛失败

这种区分是多域仿真工作的必要规则。它让增量进展仍然有用，同时避免过度声明与真实领域的对齐程度。
