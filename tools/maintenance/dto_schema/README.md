# DTO schema generator

This standard-library-only tool keeps compact C++ X-macro field lists generated
from declarative Python schemas. Generated `.inc` files remain checked in; do
not edit them directly.

Each module in `schemas/` exports one `DtoSchema`. A `Field` records `name`,
`cpp_type`, `default`, optional `comment`, and its X-macro `group`. Reserved
binding/serialization metadata (`python_name`, `readonly`, `hidden`, and
`json_key`) is present in the model but is not consumed yet.

The default header says `GENERATED by tools/maintenance/dto_schema — edit the
schema, not this file`. The two regeneration pilots override `file_header` and
`file_footer` with their pre-existing text so their checked-in output remains
byte-for-byte compatible. Schema templates are canonical LF; the CLI preserves
a uniform CRLF checkout when Git `core.autocrlf` requires one.

## Common workflow

Add or change a field in its `schemas/*.py` module, preserving field order, then
run:

```powershell
python tools/maintenance/dto_schema/generate.py --write
python tools/maintenance/dto_schema/generate.py --check
```

`--check` exits nonzero and prints a bounded unified diff when an output is
missing or stale. `--manifest` prints the machine-readable registry used by the
architecture gate.

To add a DTO family:

1. Add a schema module under `schemas/` (for an existing X-macro list,
   `parse_xmacro.py` can create the initial module without hand transcription).
2. Register its module name in `schemas/__init__.py`.
3. Run `generate.py --write`, add the generated `.inc`, and run `--check`.

Example extraction:

```powershell
python tools/maintenance/dto_schema/parse_xmacro.py path/to/fields.inc `
  --macro EF_EXAMPLE_FIELD --schema-name example_fields `
  --output-path src/example/detail/example_fields.inc `
  --schema-output tools/maintenance/dto_schema/schemas/example_fields.py
```
