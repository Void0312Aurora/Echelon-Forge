# Security Policy

## Supported Scope

This repository is maintained on a best-effort basis by a single owner.

Security fixes, if accepted, are expected to land on the current `main` branch.
Historical branches, archived documents, frozen experiment outputs, and local
artifact directories should not be assumed to receive security backports.

## Reporting a Vulnerability

Please do **not** open a public issue with exploit details, credentials,
private data, or step-by-step weaponized reproduction material.

Preferred reporting path:

1. Use GitHub's private vulnerability reporting for this repository, if that
   feature is enabled.

Fallback if private reporting is not available:

1. Open a minimal public issue requesting a private contact path.
2. Do not include exploit details, secrets, private data, or full reproduction
   steps in that issue.
3. Wait for the repository owner to acknowledge the report before sharing
   sensitive details.

## What to Include

When you make a report, include:

- the affected file, component, or workflow
- the impact you believe it has
- the shortest safe reproduction description you can provide
- any known preconditions or environment assumptions

## Response Expectations

Because this is a single-maintainer repository, response times are not
guaranteed.

Best-effort expectations:

- initial acknowledgement when the report is seen
- clarification questions if the report is incomplete
- a fix, mitigation note, or explicit decline when the report is understood

## Disclosure

Please coordinate disclosure with the repository owner until a fix or
mitigation is available, especially when the issue could expose credentials,
private data, or a broadly reusable exploit path.
